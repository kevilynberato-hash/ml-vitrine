Racional (baseado no bench com Yuri Laranja)

Sem checkpoints fixos

Nada de "no D3 decide X, no D5 decide Y". Todo dia o modelo analisa cada parceiro e recalcula a probabilidade. O parceiro pode ficar 1 dia, 3 dias ou 5 dias — depende do comportamento dele, não de uma regra rígida.

Modelo único com dia como feature

Em vez de um modelo por checkpoint, um modelo só com dia_observacao como feature. O modelo aprende sozinho que D1 tem peso diferente de D5, e que 3 dias de estagnação no D4 é pior que no D2.

Inferência diária para todos os ativos

Todo dia o script pega todos os parceiros que ainda estão na janela de 5 dias e não converteram, recalcula as features acumuladas até aquele dia e roda o modelo salvo. Decisão por percentil por dia (15/18/20/22/25%).

Ausência de engajamento é dado

Parceiro que não interage, não faz setup, não abre o app → isso é o sinal mais forte de que ele precisa de ajuda do comercial. O modelo aprende esse padrão.

Arquitetura — Modelo Único (sem checkpoints fixos)

Por que um modelo só?

Em vez de treinar um modelo para D1, outro para D3, outro para D5, D7... treinamos um modelo único onde dia_observacao é uma feature. O XGBoost aprende automaticamente as interações: "3 dias de estagnação no D4 é pior que 3 dias no D2", "setup 50% no D1 é ótimo, no D7 é alarmante".

Isso também resolve o problema de dados: se treinássemos modelos separados, o modelo D7 só veria parceiros que chegaram ao D7 (viés de sobrevivência). Com um modelo único, todos os snapshots de todos os dias entram no treino.

Algoritmo: XGBoost (Diário D1→D5)

  • 58 features (42 num + 16 cat) — split 4 vias: treino / calibracao / threshold / teste.
  • Target: target_5pdd_30d (~8.4% positivo)
  • Calibracao: IsotonicRegression (Brier CAL 0.0722, melhoria 26.9%)
  • AUC-ROC teste: 0.8846 (CI 95% [0.832, 0.935]) · AUC-PR: 0.5830 (baseline 0.076)
  • Validação: temporal (não aleatória) — sem data leakage

Como o modelo decide (inferência diária)

1. Todo dia às 7h

Script busca todos os parceiros com ganho entre D1 e D5 que ainda não fizeram 1pdd. Para cada um, calcula as features acumuladas até aquele dia (D0→hoje).

2. Modelo carregado do Workspace

O modelo já foi treinado e serializado (ml_vitrine_model.pkl). O script diário NÃO retreina — só carrega e faz model.predict_proba().

3. Percentil por dia + Flag

Para cada dia, transborda os piores N% por prob_ativar_sozinho (D1 15% → D5 25%). D6 = transbordo obrigatório de quem não fez 1pdd.

💡 Piloto A/B obrigatório

O backtest acima mede seleção, não causalidade. Para atribuir efeito ao modelo (e não à sazonalidade ou mudança do time), é obrigatório um piloto A/B controlado:

  1. Grupo controle: regra atual (Self até 5 dias, D6 obrigatório)
  2. Grupo teste: decisão do modelo (percentil por dia D1–D5)
  3. Métricas: 1pdd 5d, 5pdd 30d, share Self, conversão global
  4. Duração: 2–4 semanas para significância

# Executar UMA VEZ. Salva modelo em sandbox.
import pandas as pd
import xgboost as xgb
from sklearn.model_selection import train_test_split
import pickle

# 1. Carregar base de treino
df = spark.table("anotaai.sandbox.ml_vitrine_treino_snapshots").toPandas()

# 2. Separar features e target
target_col = "target_5pdd_30d"
id_cols = ["merchant_id", "crmdb_id", "deal_id", "merchant_name",
           "dt_ganho", "dia_observacao", "data_snapshot"]
target_cols = ["target_1pdd_5d", "target_delivery_5pdd_30d",
               "target_salao_5pdd_30d", "dias_ate_1pdd",
               "dias_ate_5pdd_del", "dias_ate_5pdd_sal"]
feature_cols = [c for c in df.columns
                if c not in id_cols + target_cols + ["target_5pdd_30d"]]

# 3. Split temporal (treino Abr-Mai, teste Jun)
df['mes'] = pd.to_datetime(df['dt_ganho']).dt.month
train = df[df['mes'].isin([4, 5])]
test  = df[df['mes'] == 6]

# 4. Treinar XGBoost (modelo UNICO — dia_observacao como feature)
scale = (train[target_col] == 0).sum() / (train[target_col] == 1).sum()
model = xgb.XGBClassifier(
    scale_pos_weight=scale,
    max_depth=6,
    learning_rate=0.05,
    n_estimators=200,
    eval_metric='auc'
)
model.fit(train[feature_cols], train[target_col])

# 5. Avaliar
from sklearn.metrics import roc_auc_score
prob = model.predict_proba(test[feature_cols])[:, 1]
print(f"AUC: {roc_auc_score(test[target_col], prob):.3f}")

# 6. Serializar em sandbox
with open("/Workspace/Users/kevilyn.berato@ifood.com.br/ml_vitrine/ml_vitrine_model.pkl", "wb") as f:
    pickle.dump({"model": model, "features": feature_cols}, f)

df_ativos["score_ativar_sozinho"] = model.predict_proba(
    df_ativos[feature_cols]
)[:, 1]

THRESHOLD = 0.30  -- calibrar com backtest
df_ativos["precisa_comercial"] = (
    df_ativos["score_ativar_sozinho"] < THRESHOLD
).astype(int)

# 4. Gate D6: quem chegou a D5 sem 1pdd transborda automatico
df_ativos.loc[
    df_ativos["dia_observacao"] >= 7,
    "precisa_comercial"
] = 1

# 5. Salvar tabela de output
output = df_ativos[[
    "merchant_id", "merchant_name", "dia_observacao",
    "score_ativar_sozinho", "precisa_comercial"
]]
spark.createDataFrame(output).write.mode("overwrite")\
    .saveAsTable("anotaai.sandbox.ml_vitrine_scoring_diario")
